1. CORE ARCHITECTURAL OVERVIEW
-----------------------------------------------------------------------------------------------------------------------
The AI Smart Safety Shield is a hybrid millisecond-level proximity lockout system that safeguards human operators
working alongside dangerous industrial machinery (such as robotic welding cells or heavy press flywheels). 

It fuses four primary layers:
  A. Frontend (Optically interactive web portal for diagnostics, logs, and gateway parameters).
  B. Express Gateway Backend (Provides API routing, JWT token guards, session management, and persistent database logs).
  C. AI Neural Edge Service (A multi-threaded Python/Flask microservice running YOLOv8 object tracking).
  D. Hardware Intercept (ESP32 microcontrollers connected via Serial triggering safety contactor relays).

3. ZERO-TO-ADVANCE STEP-BY-STEP WORKFLOWS
-----------------------------------------------------------------------------------------------------------------------
Understanding the programmatic steps from ingestion to automatic shutdown:

  WORKFLOW A: CAMERA SETUP & DB PERSISTENCE
    1. User navigates to the Camera Setup page and inputs a node name, protocol type (RTSP / USB / NVR), and address.
    2. Client-side validator checks if the IP is private (192.168.x.x). If local, it alerts the user that the local
       Edge Agent is required. If public, it sends a payload to the backend.
    3. The Express `/api/camera/save` controller receives the request. Any camera credentials (password) are securely
       encrypted using the AES-256-CBC algorithm using an environment variable key.
    4. An upsert (findOneAndUpdate) MongoDB query saves the camera configuration. It is marked as persistent.
    5. When the main Dashboard loads, the JS queries the backend `/api/camera/latest`, parses the URL, and binds it
       to the AI streaming image target:
       `cameraImg.src = "https://impactthon-ai.onrender.com/video_feed?source=" + encodeURIComponent(cam.url)`

  WORKFLOW B: REAL-TIME AI DIAGNOSTIC STREAMING & DETECTION
    1. The Python Flask service receives the camera source index or stream URL via the `/video_feed` endpoint.
    2. It instantiates an OpenCV capture object: `cap = cv2.VideoCapture(source)`.
    3. Frame Grabbing Loop:
       - Captures frames dynamically.
       - Resizes frames to 640x480 to minimize CPU consumption and ensure high-fidelity 60 FPS processing.
       - Skips frames (`FRAME_SKIP = 3`) to balance processing loads, executing YOLOv8 inference only on every 3rd frame.
    4. YOLOv8 Posture Tracking:
       - The frame is passed to YOLOv8 (`yolov8n.pt` weight matrix).
       - It filters exclusively for class `0` (person) inside the Ultralytics configuration.
       - Computes the bounding box coordinates (X1, Y1, X2, Y2) of any operator detected in the frame.
    5. Proximity Vector Mathematics:
       - The system maps a virtual "Machine Zone" (represented by a custom rectangle).
       - It calculates the Euclidean distance between the center of the worker's bounding box and the center of the machine.
       - Distance formula: `dist = sqrt((worker_cx - machine_cx)^2 + (worker_cy - machine_cy)^2)`
       - Translates the distance into safety indicators:
         * Distance > threshold: State is SAFE (system running normally). Bounding boxes are drawn in emerald GREEN.
         * Distance in buffer: State is WARNING. Bounding boxes are drawn in yellow. Alert buzzers are activated.
         * Distance < threshold (or box overlap): State is DANGER. Bounding boxes are drawn in red. Instant STOP triggered.
    6. Streaming Yield:
       - Draws corresponding diagnostic overlays (bounding boxes, labels, distance lines, status banners) on the image.
       - Encodes the frame to JPEG bytes and streams it as an MJPEG feed using standard `multipart/x-mixed-replace` MIME type.
    7. Database Logs & Alerts:
       - On state change to DANGER: The background thread converts the frame to base64, dispatches a POST request to MongoDB
         to log an incident entry, and immediately triggers an asynchronous thread to dispatch alert emails via Mailcloud.

  WORKFLOW C: HARDWARE OVERRIDE (PLC / SERIAL INTERCEPT)
    1. When the AI Status is polled as DANGER, the Python service calls the serial connection: `esp.write(b"DANGER\n")`.
    2. An ESP32 microcontroller running custom firmware on "COM3" receives the text command via standard serial buffer.
    3. The ESP32 pin pulls low/high, actuating a physical electromagnetic safety contactor relay.
    4. Power is completely cut to the industrial robot arm immediately.
    5. Once the area is cleared and status returns to SAFE, the serial command `SAFE\n` is sent, allowing a manual
       system reset to restore power to the machinery safely.

4. INTEGRATION & INSTALLATION DEPLOYMENT DIRECTIVES
-----------------------------------------------------------------------------------------------------------------------
How to install, integrate, and configure the entire system from scratch:

  STEP 1: DATABASE SETUP
    - Deploy a MongoDB cluster (e.g. MongoDB Atlas).
    - Save the connection string in your Backend `.env` file: `MONGO_URI=mongodb+srv://...`

  STEP 2: EXPRESS BACKEND RUN
    - Navigate to the `Backend` directory:
      `cd Backend`
    - Install package dependencies:
      `npm install`
    - Configure the `.env` variables:
      * `PORT=5000`
      * `ENCRYPTION_KEY=12345678901234567890123456789012` (Exactly 32 characters for AES encryption)
      * `SMTP_USER` / `SMTP_PASS` (For mail alerts)
    - Run the gateway:
      `npm start`

  STEP 3: AI EDGE STREAMER RUN
    - Navigate to the `ai` directory:
      `cd ai`
    - Install Python prerequisites:
      `pip install -r requirements.txt`
    - Run the Flask server:
      `python app.py`
    - (Optional) Run the Raspberry Pi edge streaming client:
      `cd ../raspberry_pi`
      `python app.py --camera rtsp://admin:12345@192.168.1.100:554/h264`

  STEP 4: HARDWARE PIN WIRING
    - Connect the ESP32 to the server USB port ("COM3").
    - Wire the electromagnetic safety relay contactor to the ESP32 GPIO pin (e.g., Pin 5).
    - Upload basic serial-reader firmware to actuate the relay based on incoming `DANGER` and `SAFE` text streams.
